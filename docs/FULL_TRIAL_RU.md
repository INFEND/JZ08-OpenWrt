# INFEND JZ08 — полный OpenWrt RAM-комплект v3

Аппаратный отчёт v2 от 01.11.2026: SMEM версии **1**, RAM 512 МиБ по OEM
DTB; Fastboot принял образ, но `/init` и OpenWrt не подтверждены. Через 31 с
наблюдался USB 05c6:9091, через 148 с — 05c6:9024. Это не доказывает причину
перезапуска или запуск нового Linux. Factory recovery восстановлен и перечитан
с совпадением SHA-256; BOOT/ABOOT и обе GPT повторно сверены.

v3 исправляет получение журналов и ADB в цепочке восстановления. Ядро,
модули и runtime сохранены от v2; исправление запуска ядра **не заявляется**.
В v2 помощник v15.7 возвращал код успеха даже при пустом списке устройств,
а основной наблюдатель проверял только сервер 5063. В присланных ADB-отчётах
видны два процесса Termux adb и USB-интерфейс с драйвером usbfs, но владельцы
портов и причина пустого списка не установлены.

Сначала подключи штатно загруженный роутер и получи сохранившиеся журналы
тем же полным комплектом — **без перезагрузки и записи разделов**:

```bash
python /storage/emulated/0/Download/INFEND_JZ08_OPENWRT_FULL_TRIAL_V3.zip --postmortem
```

Команда не делает RAM-тест и не запускает восстановление recovery. Она
читает доступные bootreason, uptime, last_kmsg, pstore и dmesg после строгой
идентификации MIFI/MSM8916/JZ_MIFI_LCD. Если после испытания роутер уже
перезагружался, старый журнал мог не сохраниться; его отсутствие не доказывает
отсутствие запуска Linux. Результат — один обычный итоговый ZIP-отчёт.

Используется документированный AOSP smart-socket протокол и legacy shell
Android 4.4: проверяются существующие локальные серверы 5063/5037/5046/5061/5062,
затем используется живой сеанс MIFI. Дополнительный сервер 5063 запускается
только если ни один сервер недоступен. Сервера не завершаются, USB не сбрасывается.
При нескольких физических устройствах автовыбор блокируется. Новый сеанс
RAM не меняет recovery, пока живой ADB MIFI не подтверждён. Исходные журналы
сохраняются отдельно от журналов после испытания; они не считаются новым proof.

В комплекте настоящее ядро Linux 6.12.58, полный OpenWrt initramfs с его
совпадающими модулями, русский LuCI, SSH, сетевые службы, ModemManager/rmtfs,
исходный system.img и автоматическая цепочка S24. Это полная система для
первого испытания в RAM. Постоянная установка пока не готова: Linux/OpenWrt
на физической JZ08, радио, LCD и схема постоянной загрузки ещё не проверены.

Для следующего RAM-испытания используется этот же ZIP в Download:

```bash
python /storage/emulated/0/Download/INFEND_JZ08_OPENWRT_FULL_TRIAL_V3.zip --ram-test
```

Требуются прежнее рабочее окружение S24/Magisk/Termux/EDL, USB-OTG и уже
сохранённый полный заводской backup. Его размер/SHA и обе GPT проверяются;
повторный многогигабайтный backup не создаётся и никуда не загружается.

При необходимости вход в LK2ND временно записывает **только recovery p26**,
с точной проверкой диапазонов и чтением назад. После испытания выполняется
попытка вернуть factory p26 и проверить SHA-256. При потере USB может
потребоваться ручной перезапуск устройства. Питание во время записи не отключать.

Адреса соответствуют машинному коду сохранённого LK2ND: ядро `0x80000000`,
DTB `0x81e00000`, initramfs `0x82000000`. Используется небольшое ядро без
встроенного rootfs и отдельный сжатый полный initramfs. Перекрытия запрещены.
Реальная RAM читается из OEM DTB загрузчика перед запуском; размер 512 МиБ
не предполагается. Результат статического анализа — в `board/evidence` репозитория.

Система работает около 10 минут и автоматически запрашивает возврат recovery.
USB-LuCI: `http://192.168.73.1/`, логин `root`. Новый случайный пароль каждого
запуска сохраняется **только на S24** в `Download/INFEND_JZ08_ACCESS.txt`.
Скрипт назначает IP `192.168.73.2/24` только USB-интерфейсу с меткой этого запуска.
Если ядро Android не создало RNDIS/ECM интерфейс, это отдельно попадёт в отчёт.
Наличие страницы LuCI не заявляется до её фактического получения.
LuCI может возвращать HTTP 403 с заголовком `x-luci-login-required: yes`
для штатной страницы входа; проверка распознаёт её по заголовку и HTML,
а произвольную страницу 403 успехом не считает.

В v2 USB heartbeat создаёт сам PID 1 до запуска служб OpenWrt. Признак
`/init` отделён от подтверждения procd и HTTP LuCI. При возврате штатного
Android ожидание завершается сразу и читаются доступные kernel/boot-журналы.

Перед RAM-запуском проверяются три машинных инструкции сохранённого LK2ND
и читается только его RAM-поле версии SMEM. Для версии 0 всё описание
корневой шины и reserved-memory переводится в 32-битные ячейки с сохранением
физических адресов; простая подмена одного memory/reg недопустима. Для версии
1 и выше сохраняется исходный 64-битный формат. Неизвестный код загрузчика
или неверный ответ блокирует RAM-запуск. На данной плате в v2 фактически
прочитана версия 1, поэтому ошибка legacy v0 не объясняет этот результат.

Служба USB использует совпадающий `g_ether` из этой сборки; CONFIGFS USB
в исходном ядре выключен. Для первого испытания remoteproc/Wi-Fi, LED/GPIO
потребители выключены в DTB. Драйверы и службы радио остаются в комплекте,
но их наличие не является проверкой LTE/Wi-Fi. Чужие firmware/NV не включены.
Весь видимый набор eMMC block devices до запуска procd переводится в RO;
ядро не получает root= на OEM-раздел. Настройки данного сеанса хранятся в RAM.

Один отчёт `INFEND_JZ08_OPENWRT_REPORT_*.zip` сохраняется в
`Download/XARKON_JZ08_REPORTS/`. В нём отдельно отмечаются `/init`, OpenWrt,
USB, HTTP LuCI, геометрия eMMC и восстановление p26. `--verify` повторно
проверяет текущий сеанс. `--selftest` проверяет ZIP без оборудования.

Описание протокола: [AOSP SERVICES.TXT](https://android.googlesource.com/platform/packages/modules/adb/+/refs/tags/android-platform-15.0.0_r17/SERVICES.TXT).

Если автоматический возврат factory recovery не подтвердился, верни доступный
USB/EDL и запусти тот же ZIP с `--restore`. BOOT/SYSTEM/GPT этот инструмент
не записывает. `--flash` заблокирован до независимого аппаратного результата
и разработки постоянной boot chain. Включённый исходный system.img имеет
пометку UNCONFIGURED и не предназначен для прямой записи.

Источники, точные версии и все преобразования находятся в репозитории
https://github.com/INFEND/JZ08-OpenWrt. Сборка rootfs: OpenWrt
`46ab9f3f1c0e6ac2a17efa5a3f34e466a0c2d4e0`, msm89xx
`c2e2dd5afc6ec4e8be55cfc952a1fce042e681c4`. SHA производителя и всех
полученных файлов включены в архив. Аппаратная готовность не подменяется
успешным офлайн-аудитом.
